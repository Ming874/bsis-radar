## 2. 接線

> **LD2451 的排針是 6 pin：VIN、GND、OT1、TX、RX、OT2**（手冊 V1.00 §4.2；字印在天線那一面、排針旁邊）。**背面印的 GND、TX、RX、VIN 不是排針**：那是旁邊一組小焊墊（上下兩個ㄇ形是固定腳），給另一種沒焊上去的小連接器用，間距和排針不一樣，不能照它數排針。VIN 與 GND 接反可能燒壞雷達，通電前再對一次。GND 沒接好時雷達沒有正常的地，會出現位元錯誤、斷斷續續、最後完全不輸出（[REAR_RADAR.md](REAR_RADAR.md) §2.3）。

**測速雷達（LD2451，斜照路面）**：沿用 3.x 接 C4001 的兩支腳。

| LD2451 腳位 | 接到 | 說明 |
| --- | --- | --- |
| VIN | 擴充底板 **5 V** | **一定要 5 V**（供電能力 > 300 mA）。C4001 3.3 V 也能動，LD2451 不行；有些底板的 V 排針可用跳帽切成 3.3 V，請確認 |
| GND | 擴充底板 **G** | |
| TX | **GPIO16** | 雷達送 → ESP32 收 |
| RX | **GPIO17** | ESP32 送 → 雷達收。**一定要接**：韌體要把「靠近遠離都回報、最低 1 km/h、最大 10 m」寫進雷達；沒接的話雷達照自己存的設定輸出，可能量不到路面 |
| OT1、OT2 | 不接 | |

TX／RX 是**交叉**接：雷達 TX 接 ESP32 的 RX，雷達 RX 接 ESP32 的 TX。

**輪速感測器（選用）**

| 3144 腳位（有字的面朝自己，由左到右） | 接到 |
| --- | --- |
| 1 VCC | 擴充底板 **V**（5 V；3144 需要 4.5 V 以上） |
| 2 GND | 擴充底板 **G** |
| 3 OUT | **GPIO27**（ESP32 內建上拉到 3.3 V，不用另接電阻） |

- 磁鐵固定在輻條上，3144 固定在車架上，**有字的面朝磁鐵**，經過時距離 5 mm 內。
- 3144 只對磁鐵的一個極有反應，沒反應時把磁鐵翻面。
- 碼表用的磁簧開關也可以：兩條線分別接 GPIO27 和 G。

**後方來車雷達（LD2451，朝正後方；選用）**

| LD2451 腳位 | 接到 | 說明 |
| --- | --- | --- |
| VIN | 擴充底板 **5 V** | **一定要 5 V**（供電能力 > 300 mA）。有些底板的 V 排針可用跳帽切成 3.3 V，請確認 |
| GND | 擴充底板 **G** | |
| TX | **GPIO25** | 雷達送 → ESP32 收 |
| RX | **GPIO26** | ESP32 送 → 雷達收。沒接也能用（只接收，用雷達自己存的設定）；接了 ESP32 才能寫入偵測設定 |
| OT1、OT2 | 不接 | |

兩顆 LD2451 的鮑率都由韌體自動偵測（原廠 115200）。不確定接到哪兩支腳時，燒錄 `firmware/diagnostics/LD2451Probe` 會自動找出來（[診斷工具](../firmware/diagnostics/README.md)）。兩顆同時用的峰值電流約 340 mA，USB 供電不足時改用行動電源。

## 3. 安裝雷達

精度主要由這一步決定，原理見 [ALGORITHM.md](ALGORITHM.md) §0.2、§3。

**測速雷達**

| 項目 | 要求 |
| --- | --- |
| 位置 | 後貨架尾端（原本 C4001 的位置），雷達在**後輪後方**，朝後下方照路面 |
| 模組方向 | 天線面朝後下方；**模組直立、排針朝上**再往下俯。兩組接收天線左右排列，量到的角度才是左右的水平角（韌體用它修正斜向的目標） |
| 俯角 θ | **25～35°**（預設 30°），在平地上量。LD2451 的距離是整數公尺，太陡時路面離雷達不到 1 m，可能量不到 |
| 高度 h | 天線面中心到地面 0.6～0.8 m（預設 0.70 m） |
| 淨空 | 波束內不能有擋泥板、反光片、貨架上的東西、騎士腳跟；天線面前方不要加殼 |
| 固定 | 鎖緊，騎乘時角度不能變；線材不能碰到輪子 |
| 和後方雷達 | 兩顆是同型號、同頻段，盡量不要照到彼此、視野不要重疊（測速雷達往下、後方雷達水平） |

**量角度與高度**
- **俯角**：車停在平地、騎士坐上車。手機水平儀貼在雷達**背面**，讀數就是天線面法線與水平面的夾角。
- **高度**：量天線面中心到地面的垂直距離。

**確認**：從側面看，雷達斜向下指著後輪後方約 1.2 m 的路面（高度 0.7 m、30° 時；斜距 1.4 m）。

**後方來車雷達 LD2451（選用）**：裝在座管或後貨架，**模組直立、排針朝上**，天線面朝**正後方**、保持水平（可稍微上仰 0～5°），離地 0.6～1 m。天線前方不能有擋泥板、反光片；背後不要有會動的東西（騎士的腳），可加一片金屬板擋背瓣。詳見 [REAR_RADAR.md](REAR_RADAR.md) §4。

## 4. 燒錄韌體

### 一鍵燒錄（不需要 Arduino IDE）

1. USB 線插在 **ESP32 板子本身**的 USB-C 孔（EN／BOOT 按鈕旁）。擴充底板的 USB 孔只供電、不能燒錄。
2. 打開 `firmware` 資料夾，雙擊 **`flash.bat`**。
3. 第一次在這台電腦燒錄時：
   - 顯示「沒有 CH340 驅動」：輸入 `Y`，在使用者帳戶控制按「是」，安裝視窗按「INSTALL」；裝好後拔插 USB，再雙擊一次。
   - 沒有 esptool 時，會自動從 Espressif 官方 GitHub 下載（需要網路）。

**確認**：

```text
✓ 燒錄完成
確認 ESP32 開機訊息…
      === BSIS 對地測速雷達 v4.0.0 ===
      [藍牙] 已開始廣播：BSIS-Speed
      [測速雷達] LD2451：TX → GPIO16、RX → GPIO17，尋找鮑率中...
      [後方雷達] LD2451：TX → GPIO25、RX → GPIO26，尋找鮑率中...
      [測速雷達] 115200 bps，指令有回覆
      [測速雷達] 讀回目標參數：最大距離 10 m、方向 2、最低速度 1 km/h、延遲 1 s
      [測速雷達] 設定完成，開始讀取資料
✓ ESP32 已經在執行新韌體！
```

- 測速雷達第一次開機會多一行「已寫入目標參數：10 m、靠近遠離都回報、1 km/h、延遲 1 s」，之後讀回來一樣就不再寫（保護雷達的 flash）。
- 出現「收得到資料，但指令沒有回覆：只接收」代表那顆雷達的 RX 沒接到 ESP32。後方雷達照樣能用；**測速雷達請一定接好**（§2）。沒接 LD2451 時會每隔一段時間重試。
- 從 3.x（C4001）升級時會印「從 3.x（C4001）升級：沿用安裝角度、高度、朝向、輪周長…校正係數回到 1」：安裝參數保留，但換了雷達要重新校正（§9）。從 2.x（後方來車版）升級時舊的參數不會沿用。

修改程式後的編譯與燒錄見 [firmware/README.md](../firmware/README.md)。

## 5. 確認 ESP32

板子上的藍色 LED：

| LED | 意思 |
| --- | --- |
| 慢閃（0.5 秒） | 正常，等待手機連線 |
| 快閃（0.15 秒） | 手機已連線 |
| 恆亮 | 正在量到地面速度（追蹤中） |
| 每秒閃兩下 | 雷達離線或初始化中（開機約 5 秒內屬正常） |

**確認**：開機 5 秒後是慢閃。

## 6. 手機連線

1. ESP32 接上電。
2. 手機開啟藍牙，用 Chrome 打開 <https://bsis.mingchen.dev>。
3. 網頁會跳出「安裝 BSIS 測速 App」：按「**安裝**」，之後從主畫面打開（全螢幕、沒有網路也打得開，資料和瀏覽器共用）。不想安裝就按「之後再說」。
4. 按「**連線**」，選 **BSIS-Speed**。要求「附近裝置」或位置權限時請允許。

| 瀏覽器 | 支援 |
| --- | --- |
| Android Chrome | 支援 |
| 電腦 Chrome／Edge（需有藍牙） | 支援 |
| iPhone Safari | 不支援，請改用 Bluefy |
| Brave | 預設關閉；`brave://flags` → Web Bluetooth → Enabled |

ESP32 一次只能連一台裝置。沒有硬體時，可以開 <https://bsis.mingchen.dev/?demo> 看示範資料。

**確認**：右上角顯示「● 已連線」，LED 變快閃。

騎車時按速度頁的「**騎乘模式**」：全螢幕、只顯示速度、後方來車與本次行程，超速時整個畫面變紅；後方來車時右側直條與畫面邊框變黃（注意）或紅（危險）。按「結束」或返回鍵離開。iPhone 的 Bluefy 不要加到主畫面：主畫面的 App 會改用 Safari 的引擎，不能用藍牙。

## 7. 設定安裝參數

到「**校正**」頁的「安裝幾何」：

| 參數 | 填入 |
| --- | --- |
| 俯角 θ | §3 量到的角度 |
| 離地高度 h | §3 量到的高度 |
| 雷達朝向 | 朝後 |
| 速度模型 | 固定角度（預設） |

按「**套用到裝置**」。安裝參數只影響 ESP32 的換算與距離窗口，不必重新設定雷達，套用後立刻生效。

**確認**：示意圖的波束打在車輪後方；「斜距」與實際安裝相符；「校正 → 設定進度」的「測速雷達」是「在線，偵測設定已寫入雷達」。

## 8. 第一次檢查

**這一步是 4.0 最重要的檢查**：LD2451 是設計來偵測車輛的雷達，會不會把路面回報成目標還沒實際驗證過（[ALGORITHM.md](ALGORITHM.md) §0.7）。推著車在柏油路上走（約 4～6 km/h），看「**數據**」頁的「測速雷達」：

| 項目 | 正常 | 不正常時 |
| --- | --- | --- |
| 目標數 N | 推著走時 ≥ 1，停下來時 0 | 一直是 0 → 雷達量不到路面：俯角試 25°～35°、`GSNR` 調低到 3（設定 → 裝置參數）；仍然沒有就是 LD2451 不適合 |
| 判斷 FV | 大多是「採用」 | 大多「方向相反」→ 朝向設反，頁面上方會出現切換按鈕；大多「窗口外」→ 角度或高度填錯，或照到遠處的東西 |
| 距離 RD、角度 A | 1～3 m、±20° 內 | 一直是很遠的距離 → 波束沒打到路面 |
| 可用比例 Q | ≥ 50% | 雷達被擋住、角度太淺、門檻太高 |
| 資料框 Hz | 推著走時穩定（記下這個數字） | 遠低於 5 Hz → 回報給開發者調參數（§0.5） |
| 速度頁 | 走路速度約 4～6 km/h，停下後 1 秒內變「靜止」 | 一直「擷取中」→ 回波太少 |

這時還沒校正，速度通常**偏低約 5～15%**：寬波束的路面回波偏向正下方（[ALGORITHM.md](ALGORITHM.md) §3.2、§0.6），下一步校正會修正。

**後方來車雷達（有裝 LD2451 時）**：到「校正 → 後方雷達」，請另一個人從車後 10 m 走（或推另一台車）過來：

| 項目 | 正常 | 不正常時 |
| --- | --- | --- |
| 狀態 | 「後方安全」，走近時變「後方有車接近」 | 「後方雷達離線」→ 檢查 5 V、GND、TX → GPIO25 |
| 俯視圖 | 點從下面往上接近 | 點在相反的一邊 → 設定頁「後方來車警示 → 雷達畫面左右對調」 |
| 數據頁「後方雷達」的速度欄 | 走近時是「靠近」 | 顯示「遠離」→ 方向位元組相反，見 [REAR_RADAR.md](REAR_RADAR.md) §10 |
| 模式 | 完整 | 「只接收」→ LD2451 RX 沒接到 GPIO26（照樣能用，只是 ESP32 無法寫入設定） |

走路速度約 5 km/h，剛好在最低接近速度（`RSPD` 預設 5）附近；偵測不穩定時暫時把 `RSPD` 調成 2 測試，測完改回來。

## 9. 校正

網頁 3.2 起拿掉了「校正係數」與「精度驗證」（我們沒有使用輪速感測器），網頁的畫面不會再改 `CAL`。韌體照樣把速度與里程乘上 ESP32 存的 `CAL`：出廠值 1.0000，沒校正時讀值通常偏低（§8）。**從 3.x 升級到 4.0（換成 LD2451）時 `CAL` 會回到 1，一定要重新校正。** 用已知距離手動算：

1. 在平直的柏油路量好 **100 m**（至少 30 m），起點、終點做記號。操場直線跑道最方便。
2. 車停在起點，前輪對準記號，記下「**數據**」頁的「**雷達里程 DR**」。
3. 以平常的速度騎到終點，慢慢停下，前輪停在終點記號上，再記一次 DR。兩次相減就是雷達量到的距離。
4. 重複 **3 趟**，計算 `CAL新 = CAL舊 × 實際距離總和 ÷ 雷達距離總和`。目前的 `CAL` 在「數據 → 主控台」送 `GET`，回覆的 `CFG` 行裡有 `CAL=`。
5. 在主控台（或 USB 序列埠，115200 bps）送 `CAL <新係數>`，例如 `CAL 1.1520`（0.5～2.0，4 位小數），回覆 `OK saved` 就存進 ESP32 了。

**確認**：
- 各趟算出來的係數應該接近，離散 < 2%。
- 新係數通常在 1.0～1.2 之間（30° 安裝的模擬值約 1.09）；和 1 差超過 40% 時，通常代表角度、朝向或距離有誤。
- 「設定 → 維護 → 恢復預設值」會把 `CAL` 改回 1.0000。

### 什麼時候要重新校正

- 改了安裝角度或高度。
- 換了速度模型。
- 主要路面改變。
- 換胎。

## 10. 驗收

在**封閉場地**、有人看守的情況下進行。測試期間在「數據」頁按「開始記錄」，每一項結束後「停止並下載」CSV。

### 10.1 第一項：LD2451 量得到路面（一定要先做）

LD2451 是設計來偵測車輛的雷達，斜照路面時會不會穩定回報路面、近距離盲區多大、有目標時一秒幾個資料框，都還沒實測（[ALGORITHM.md](ALGORITHM.md) §0.7）。LD2451 的測速範圍是 0～120 km/h，不像 C4001 有約 16.7 km/h 的上限。

1. 記錄 CSV，在平直路面上從 0 **慢慢加速到 30 km/h**，維持 10 秒，再慢慢減速到停。
2. 俯角 25°、30°、35° 各騎一次（每次改完「校正 → 安裝幾何」再騎）。
3. 用電腦分析（`--angle`、`--height` 填當時的設定）：

   ```powershell
   python firmware\diagnostics\analyze_ride.py bsis-speed_xxxx.csv --angle 30 --height 0.70
   ```

4. 對照結果：

| 觀察 | 代表 | 處理 |
| --- | --- | --- |
| 報告的「可用比例」高、速度頁一路連續到 30 km/h | LD2451 量得到路面 | 合格；選可用比例最高的俯角，記下資料框頻率 |
| 低速可以、高速常常「暫時失去回波」或「訊號中斷」 | 高速時路面回波不穩定 | 試別的俯角、`GSNR 3`；記錄在紀錄表 |
| 幾乎都是「沒有目標」或「窗口外」 | LD2451 不把路面當目標，或照到的都是遠處的東西 | 換角度仍然不行時，LD2451 不適合當測速雷達（ALGORITHM.md §0.7、§11） |
| 後方雷達開著時測速雷達的可用比例明顯變低 | 兩顆 LD2451 互相干擾 | 把兩顆的視野錯開（§3）；記錄在紀錄表 |

### 10.2 驗收項目與合格標準

| # | 項目 | 方法 | 合格標準 |
| --- | --- | --- | --- |
| A | 靜止 | 車停著、騎士坐上車，60 秒 | 速度顯示 0（靜止）；誤顯示 > 1 km/h 的累計時間 < 1 秒 |
| B | 起步 | 推車從靜止走到 4～6 km/h | 1 秒內開始顯示速度；可用比例 Q ≥ 50% |
| C | 停車 | 15 km/h 煞車到停 | 停下後 1.5 秒內顯示「靜止」，不出現「訊號中斷」 |
| D | 距離精度（校正後） | 校正用的路面，另外量 200 m，騎 3 趟（起終點停住） | 每趟誤差 ≤ ±3%，3 趟平均絕對誤差 ≤ 2% |
| E | 與輪速一致（有輪速感測器時） | 15～25 km/h 穩定騎乘 2 分鐘並記錄 CSV，用 `analyze_ride.py` 看雷達與輪速的比對 | 里程誤差 ≤ ±2%；速度差 RMS ≤ 1.5 km/h |
| F | 量得到路面、測速範圍 | §10.1 | 0～30 km/h 一路連續；記錄最佳俯角與資料框頻率 |
| G | 其他路面（記錄用） | 水泥、碎石、潮濕路面各重複 D 一次 | 記錄誤差；預期乾燥路面差 ±1～3%，潮濕路面誤差大或量不到（[ALGORITHM.md](ALGORITHM.md) §3.4） |
| H | 超速警示（先完成 §9 與 F） | 手機裝在龍頭上、開騎乘模式、媒體音量開啟，記錄 CSV。從 20 km/h 慢慢加速到約 28 km/h 維持 10 秒，再慢慢減速到 20 km/h；另在 24～26 km/h 巡航 1 分鐘，記下警示進出的次數 | 速度頁達到 25.0 km/h 後約 1 秒內變紅並響兩聲（騎乘模式整個畫面變紅）；降到 24 km/h 以下約 1 秒後解除；輪速（參考）穩定 ≥ 26 km/h 時一直是紅的；騎乘中聽得到提示音。規則與限制見 [SPEED_ALERT.md](SPEED_ALERT.md) |

D 的距離誤差和 §9 一樣用「數據」頁的「雷達里程 DR」量：起點、終點各記一次，相減就是雷達量到的距離。

## 問題排除

| 狀況 | 可能原因 | 處理 |
| --- | --- | --- |
| `flash.bat` 找不到 ESP32 | USB 插在擴充底板；線只能充電 | 改插 ESP32 板子本身的 USB-C 孔；換線 |
| 顯示「沒有 CH340 驅動」 | 第一次在這台電腦使用 | 依提示安裝官方驅動，裝完拔插 USB |
| 燒錄失敗 | COM 埠被占用；沒進入燒錄模式 | 關閉其他序列埠程式；按住 BOOT 再燒錄，看到 `Connecting...` 後放開 |
| LED 一直每秒閃兩下 | 測速雷達沒接好或沒電 | 檢查 VIN（5 V）／GND、雷達 TX → GPIO16、RX → GPIO17 |
| 網頁顯示「韌體過舊」或「韌體與網頁版本不一致」 | ESP32 還是 2.x（後方來車版）或 3.x（C4001 版） | 用 `flash.bat` 燒錄 4.0 |
| 找不到 BSIS-Speed | 已被其他裝置連線；手機藍牙沒開 | 中斷其他裝置；開啟藍牙與「附近裝置」權限 |
| 一直「靜止」或「擷取中」，車子在動 | 波束沒照到路面；朝向設反；回波太弱 | 看數據頁的 FV：「窗口外」→ 檢查角度與高度；「方向相反」→ 切換朝向；「沒有目標」→ 調低 `GSNR`、試別的俯角、檢查有沒有東西擋住（§10.1） |
| 頁面上方提示「方向與設定相反」 | 雷達朝向（DIR）設反；或測速雷達一直看到後方來車 | 車子在前進時才按提示的按鈕切換 |
| 頁面上方提示「測速雷達只接收」 | 測速 LD2451 的 RX 沒接到 GPIO17 | 接上 RX：雷達才會用韌體的設定（靠近遠離都回報、最低 1 km/h） |
| 速度偏低 5～15% | 還沒校正（從 3.x 升級時 `CAL` 回到 1） | §9 |
| 超速時沒有警示，或要騎得比 25 km/h 快很多才警示 | 還沒校正（讀值偏低）；高速時回波不穩定；潮濕路面 | §9；§10.1（[SPEED_ALERT.md](SPEED_ALERT.md) §2） |
| 畫面變紅但沒有聲音 | 手機靜音或媒體音量為 0；開網頁後還沒點過畫面；「提示音」關閉 | 調高媒體音量；按設定頁「超速警示 → 測試」 |
| 換到另一種路面就不準 | 寬波束的偏差隨路面改變 | 在該路面重新校正；根本改善是收窄波束（ALGORITHM.md §11） |
| 下雨天常常「訊號中斷」 | 潮濕路面接近鏡面，24 GHz 回波很弱 | 已知限制（ALGORITHM.md §3.4） |
| 速度跳動大 | 波束照到車輪、擋泥板；安裝鬆動 | 確認 §3 的淨空與固定；數據頁的散佈圖應該集中在理論曲線附近 |
| 停著時偶爾跳出速度 | 波束內有人走動；車架振動 | 一兩筆不會觸發（要 3 筆一致）；持續出現就檢查波束內的東西 |
| 騎車時沒畫面 | 螢幕關閉後瀏覽器暫停網頁 | 「設定 → 連線時保持螢幕常亮」 |
| 「後方雷達離線」 | LD2451 沒電、TX 沒接到 GPIO25 | 檢查 5 V、GND、TX → GPIO25；序列埠會印出重試的原因 |
| 後方雷達「只接收」 | LD2451 RX 沒接到 GPIO26 | 照樣能用；要讓 ESP32 寫入最低速度與訊噪比就接上 RX |
| 後方來車沒有警示 | 車子接近速度低於 `RSPD`；車在彎道上、不在雷達正後方；網頁的後方警示關閉 | 校正頁的俯視圖看得到點嗎？設定頁「後方來車警示」 |
| 後方常常誤報 | 旁邊車道的車（分不出車道）；雷達背後有東西在動；訊噪比門檻太低；測速雷達的干擾 | 背後加金屬板；調高 `RSNR`（接了 RX 才寫得進去）；把兩顆雷達的視野錯開 |

還是不行：「數據 → 指令主控台」輸入 `GET` 看 ESP32 有沒有回覆 `CFG …`；或在 `firmware` 資料夾執行 `.\arduino.ps1 monitor`，看序列埠的完整訊息。
