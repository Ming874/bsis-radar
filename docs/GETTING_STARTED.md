## 1. 材料

| 項目 | 規格／備註 |
| --- | --- |
| ESP32 DevKit ＋ 擴充底板 | USB 晶片為 CH340 |
| DFRobot C4001 毫米波雷達（25 m 版，SEN0609） | 附 4 pin 線 |
| 固定件 | 能把雷達固定在後貨架尾端、可調俯角的支架（3D 列印或鋁片）。俯角要能鎖定 |
| USB-C 傳輸線 | 要能傳資料（有些線只能充電） |
| Windows 電腦 | 燒錄用，不需要安裝 Arduino IDE |
| 手機 | Android 用 Chrome；iPhone 用 Bluefy 瀏覽器 |
| 行動電源 | 5 V USB |
| 量具 | 捲尺（量高度與校正距離）、手機水平儀 App（量俯角） |
| （選用）3144 霍爾開關 ＋ 釹鐵硼磁鐵 | 輪速感測器，當校正與驗證的參考值；TO-92 三腳，不要買「49E 線性型」 |

## 2. 接線

| C4001 腳位 | 接到 | 說明 |
| --- | --- | --- |
| VIN | 擴充底板 **V** | 5 V |
| GND | 擴充底板 **G** | |
| TX | **GPIO16** | 雷達送 → ESP32 收 |
| RX | **GPIO17** | ESP32 送 → 雷達收 |
| OUT | 不接 | |

TX／RX 是**交叉**接：雷達 TX 接 ESP32 的 RX（16），雷達 RX 接 ESP32 的 TX（17）。

**輪速感測器（選用）**

| 3144 腳位（有字的面朝自己，由左到右） | 接到 |
| --- | --- |
| 1 VCC | 擴充底板 **V**（5 V；3144 需要 4.5 V 以上） |
| 2 GND | 擴充底板 **G** |
| 3 OUT | **GPIO27**（ESP32 內建上拉到 3.3 V，不用另接電阻） |

- 磁鐵固定在輻條上，3144 固定在車架上，**有字的面朝磁鐵**，經過時距離 5 mm 內。
- 3144 只對磁鐵的一個極有反應，沒反應時把磁鐵翻面。
- 碼表用的磁簧開關也可以：兩條線分別接 GPIO27 和 G。

## 3. 安裝雷達

精度主要由這一步決定，原理見 [ALGORITHM.md](ALGORITHM.md) §3、§4。

| 項目 | 要求 |
| --- | --- |
| 位置 | 後貨架尾端，雷達在**後輪後方**，朝後下方照路面 |
| 模組方向 | 雷達有元件的那面（天線面）朝後下方；**排針那條邊（26 mm 邊）保持水平、與後輪軸平行** |
| 俯角 θ | 40～45°（預設 45°），在平地上量 |
| 高度 h | 天線面中心到地面 0.6～0.8 m（預設 0.70 m） |
| 淨空 | 波束內不能有擋泥板、反光片、貨架上的東西、騎士腳跟；天線面前方不要加殼 |
| 固定 | 鎖緊，騎乘時角度不能變；線材不能碰到輪子 |

**為什麼排針邊要水平**：C4001 的波束是 100° × 40°，窄的 40° 要落在「含行進方向的鉛直面」上。依天線排列推論，40° 平面沿著 30 mm 的邊，所以 26 mm 的排針邊要水平、朝左右。方向轉錯 90°，偏差會從約 −14% 變成 −30%～−90%。

**量角度與高度**
- **俯角**：車停在平地、騎士坐上車。手機水平儀貼在雷達**背面**，讀數就是天線面法線與水平面的夾角。
- **高度**：量天線面中心到地面的垂直距離。

**（選用）確認波束方向**：雷達朝向 3 m 外的牆，每轉 5° 記一次能量（數據頁的 E）。分別在「排針水平」和「排針垂直」各轉一圈；能量降到一半時角度範圍較窄的那一圈，就是 40° 那一軸。

**確認**：從側面看，雷達斜向下指著後輪後方約 0.7 m 的路面（高度 0.7 m、45° 時）。

## 4. 燒錄韌體

### 一鍵燒錄（不需要 Arduino IDE）

1. USB 線插在 **ESP32 板子本身**的 USB-C 孔（EN／BOOT 按鈕旁）。擴充底板的 USB 孔只供電、不能燒錄。
2. 打開 `firmware` 資料夾，雙擊 **`flash.bat`**。
3. 第一次在這台電腦燒錄時：
   - 顯示「沒有 CH340 驅動」：輸入 `Y`，在使用者帳戶控制按「是」，安裝視窗按「INSTALL」；裝好後拔插 USB，再雙擊一次。
   - 沒有 esptool 時，會自動從 Espressif 官方 GitHub 下載（需要網路）。

**確認**：

```text
✓ 燒錄完成
確認 ESP32 開機訊息…
      === BSIS 對地測速雷達 v3.0.0 ===
      [藍牙] 已開始廣播：BSIS-Speed
      [雷達] 讀回 getRange：0.620 2.400
      [雷達] 初始化完成，開始讀取測速資料
✓ ESP32 已經在執行新韌體！
```

- `getRange` 讀回的是雷達實際存下的距離窗口。
- 從 2.x（後方來車版）升級時，舊的參數不會沿用，會改用 3.0 的預設值。

修改程式後的編譯與燒錄見 [firmware/README.md](../firmware/README.md)。

## 5. 確認 ESP32

板子上的藍色 LED：

| LED | 意思 |
| --- | --- |
| 慢閃（0.5 秒） | 正常，等待手機連線 |
| 快閃（0.15 秒） | 手機已連線 |
| 恆亮 | 正在量到地面速度（追蹤中） |
| 每秒閃兩下 | 雷達離線或初始化中（開機約 5 秒內屬正常） |

**確認**：開機 5 秒後是慢閃。

## 6. 手機連線

1. ESP32 接上電。
2. 手機開啟藍牙，用 Chrome 打開 <https://bsis.mingchen.dev>。
3. 按「**連線**」，選 **BSIS-Speed**。要求「附近裝置」或位置權限時請允許。
4. 建議在 Chrome 選單選「加入主畫面」，之後像 App 一樣全螢幕開啟。

| 瀏覽器 | 支援 |
| --- | --- |
| Android Chrome | 支援 |
| 電腦 Chrome／Edge（需有藍牙） | 支援 |
| iPhone Safari | 不支援，請改用 Bluefy |
| Brave | 預設關閉；`brave://flags` → Web Bluetooth → Enabled |

ESP32 一次只能連一台裝置。沒有硬體時，可以開 <https://bsis.mingchen.dev/?demo> 看示範資料。

**確認**：右上角顯示「● 已連線」，LED 變快閃。

## 7. 設定安裝參數

到「**校正**」頁的「安裝幾何」：

| 參數 | 填入 |
| --- | --- |
| 俯角 θ | §3 量到的角度 |
| 離地高度 h | §3 量到的高度 |
| 雷達朝向 | 朝後 |
| 速度模型 | 固定角度（預設） |

按「**套用到裝置**」。ESP32 會把新的地面距離窗口寫進雷達，約 4 秒內顯示「雷達離線」，之後自動恢復。

**確認**：示意圖的波束打在車輪後方；「斜距」與實際安裝相符。

## 8. 第一次檢查

推著車在柏油路上走（約 4～6 km/h），看「**數據**」頁：

| 項目 | 正常 | 不正常時 |
| --- | --- | --- |
| 判斷 FV | 大多是「採用」 | 大多「方向相反」→ 朝向設反，頁面上方會出現切換按鈕；大多「距離窗口外」→ 角度或高度填錯 |
| 可用比例 Q | ≥ 50% | 雷達被擋住、角度太淺、門檻太高 |
| 散佈圖 | 點落在灰色窗口內、理論曲線附近 | 點散在窗口外 → 波束照到其他東西 |
| 速度頁 | 走路速度約 4～6 km/h，停下後 1 秒內變「靜止」 | 一直「擷取中」→ 回波太少 |

這時還沒校正，速度通常**偏低 10～20%**：寬波束的路面回波偏向正下方（[ALGORITHM.md](ALGORITHM.md) §3.2），下一步校正會修正。

## 9. 校正

到「**校正**」頁的「校正係數」。

### 方式 A：已知距離（不需要輪速感測器）

1. 在平直的柏油路量好 **100 m**（至少 30 m），起點、終點做記號。操場直線跑道最方便。
2. 車停在起點，前輪對準記號，按「**開始一趟**」。
3. 以平常的速度騎到終點，慢慢停下，前輪停在終點記號上，按「**結束這一趟**」。
4. 輸入實際距離，按「加入結果」。
5. 重複 **3 趟**，按「**套用到裝置**」。

**確認**：
- 各趟的「誤差」應該接近，離散 < 2%。
- 新係數通常在 1.1～1.3 之間。
- 新係數相差超過 40% 時，網頁會再確認一次；這通常代表角度、朝向或距離有誤。

### 方式 B：輪速感測器

1. 「設定 → 裝置參數 → 輪周長」設成你的輪胎。最準的量法是滾動法：氣門嘴朝下做記號，人坐上車往前滾一圈，量兩個記號的距離。
2. 「校正 → 輪速感測器」，按「開始一趟」，正常騎 **300 m 以上**，避免急煞與上下人行道。
3. 按「結束這一趟」→「加入結果」→「套用到裝置」。

### 什麼時候要重新校正

- 改了安裝角度或高度。
- 換了速度模型。
- 主要路面改變。
- 換胎。

## 10. 驗收

在**封閉場地**、有人看守的情況下進行。測試期間在「數據」頁按「開始記錄」，每一項結束後「停止並下載」CSV。

### 10.1 第一項：C4001 測速上限（一定要先做）

C4001 的測速上限在規格書裡互相矛盾（徑向 3 或 10 m/s，[ALGORITHM.md](ALGORITHM.md) §2.2），而且決定了能量到多快。

1. 記錄 CSV，在平直路面上從 0 **慢慢加速到 30 km/h**，維持 10 秒，再慢慢減速。
2. 用電腦分析：

   ```powershell
   python firmware\diagnostics\analyze_ride.py bsis-speed_xxxx.csv --angle 45 --height 0.70
   ```

3. 對照結果：

| 觀察 | 代表 | 處理 |
| --- | --- | --- |
| 序列埠或主控台出現「自動把 VMAX 調為 10.0」 | 上限其實 ≥ 10 m/s | 不用處理，韌體已自動調整 |
| 報告「沒有截斷或折疊」、速度頁一路連續 | 上限 ≥ 量到的最大值 | 合格 |
| 報告「疑似折疊」、速度頁仍連續 | 上限約 3.28 m/s，韌體已還原折疊 | 合格；把 VMAX 設成報告建議的值 |
| 報告「疑似截斷」，約 16 km/h 以上顯示「超出測速上限」 | 上限約 3.28 m/s，而且會截斷 | 這是 C4001 的硬體限制：只能量到約 16.7 km/h（45°）；改善方式見 ALGORITHM.md §11 |

### 10.2 驗收項目與合格標準

| # | 項目 | 方法 | 合格標準 |
| --- | --- | --- | --- |
| A | 靜止 | 車停著、騎士坐上車，60 秒 | 速度顯示 0（靜止）；誤顯示 > 1 km/h 的累計時間 < 1 秒 |
| B | 起步 | 推車從靜止走到 4～6 km/h | 1 秒內開始顯示速度；可用比例 Q ≥ 50% |
| C | 停車 | 15 km/h 煞車到停 | 停下後 1.5 秒內顯示「靜止」，不出現「訊號中斷」 |
| D | 距離精度（校正後） | 校正用的路面，另外量 200 m，騎 3 趟（起終點停住） | 每趟誤差 ≤ ±3%，3 趟平均絕對誤差 ≤ 2% |
| E | 與輪速一致（有輪速感測器時） | 15～25 km/h 穩定騎乘 2 分鐘，看「精度驗證」 | 里程誤差 ≤ ±2%；速度差 RMS ≤ 1.5 km/h |
| F | 測速範圍 | §10.1 | 依 §10.1 的處理方式記錄結論 |
| G | 其他路面（記錄用） | 水泥、碎石、潮濕路面各重複 D 一次 | 記錄誤差；預期乾燥路面差 ±1～3%，潮濕路面誤差大或量不到（[ALGORITHM.md](ALGORITHM.md) §3.4） |
| H | 超速警示（先完成 §9 與 F） | 手機裝在龍頭上、媒體音量開啟，記錄 CSV。從 20 km/h 慢慢加速到約 28 km/h 維持 10 秒，再慢慢減速到 20 km/h；另在 24～26 km/h 巡航 1 分鐘，記下警示進出的次數 | 速度頁達到 25.0 km/h 後約 1 秒內變紅並響兩聲；降到 24 km/h 以下約 1 秒後解除；輪速（參考）穩定 ≥ 26 km/h 時一直是紅的；騎乘中聽得到提示音。規則與限制見 [SPEED_ALERT.md](SPEED_ALERT.md) |

D 的距離誤差可以直接用「校正 → 開始一趟」量，結束時會顯示雷達的誤差；只要按「放棄這一趟」，就不會改到校正係數。

## 問題排除

| 狀況 | 可能原因 | 處理 |
| --- | --- | --- |
| `flash.bat` 找不到 ESP32 | USB 插在擴充底板；線只能充電 | 改插 ESP32 板子本身的 USB-C 孔；換線 |
| 顯示「沒有 CH340 驅動」 | 第一次在這台電腦使用 | 依提示安裝官方驅動，裝完拔插 USB |
| 燒錄失敗 | COM 埠被占用；沒進入燒錄模式 | 關閉其他序列埠程式；按住 BOOT 再燒錄，看到 `Connecting...` 後放開 |
| LED 一直每秒閃兩下 | 雷達沒接好或沒電 | 檢查 VIN／GND、TX↔16、RX↔17 |
| 網頁顯示「韌體過舊」 | ESP32 還是 2.x（後方來車版） | 用 `flash.bat` 燒錄 3.0 |
| 找不到 BSIS-Speed | 已被其他裝置連線；手機藍牙沒開 | 中斷其他裝置；開啟藍牙與「附近裝置」權限 |
| 一直「靜止」或「擷取中」，車子在動 | 波束沒照到路面；朝向設反；回波太弱 | 看數據頁的 FV：「距離窗口外」→ 檢查角度與高度；「方向相反」→ 切換朝向；「沒有目標」→ 降低雷達門檻、檢查有沒有東西擋住 |
| 頁面上方提示「方向與設定相反」 | 雷達朝向（DIR）設反 | 按提示的按鈕切換 |
| 速度約 16～17 km/h 以上就「超出測速上限」 | C4001 測速上限約 3.28 m/s 而且會截斷 | 見 §10.1；可把俯角加大到 50° 換取一點範圍，但角度誤差會變大 |
| 速度偏低 10～20% | 還沒校正 | §9 |
| 超速時沒有警示，或要騎得比 25 km/h 快很多才警示 | 還沒校正（讀值偏低）；C4001 會截斷，約 16.7 km/h 以上量不到；潮濕路面 | §9；§10.1；設定頁「超速警示」下方的提示（[SPEED_ALERT.md](SPEED_ALERT.md) §2） |
| 畫面變紅但沒有聲音 | 手機靜音或媒體音量為 0；開網頁後還沒點過畫面；「提示音」關閉 | 調高媒體音量；按設定頁「超速警示 → 測試」 |
| 換到另一種路面就不準 | 寬波束的偏差隨路面改變 | 在該路面重新校正；根本改善是收窄波束（ALGORITHM.md §11） |
| 下雨天常常「訊號中斷」 | 潮濕路面接近鏡面，24 GHz 回波很弱 | 已知限制（ALGORITHM.md §3.4） |
| 速度跳動大 | 波束照到車輪、擋泥板；安裝鬆動 | 確認 §3 的淨空與固定；數據頁的散佈圖應該集中在理論曲線附近 |
| 停著時偶爾跳出速度 | 波束內有人走動；車架振動 | 一兩筆不會觸發（要 3 筆一致）；持續出現就檢查波束內的東西 |
| 騎車時沒畫面 | 螢幕關閉後瀏覽器暫停網頁 | 「設定 → 連線時保持螢幕常亮」 |

還是不行：「數據 → 指令主控台」輸入 `GET` 看 ESP32 有沒有回覆 `CFG …`；或在 `firmware` 資料夾執行 `.\arduino.ps1 monitor`，看序列埠的完整訊息。
