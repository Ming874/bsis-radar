## 1. 準備材料

| 項目 | 備註 |
| --- | --- |
| ESP32 DevKit ＋ 擴充底板 | 板子上的 USB 晶片是 CH340 |
| DFRobot C4001 25 m 毫米波雷達 | 附 4 pin 線 |
| USB-C 傳輸線 | **要能傳資料**（有些線只能充電） |
| Windows 電腦 | 燒錄用；不需要安裝 Arduino IDE |
| Android 手機 | 用 Chrome；iPhone 請安裝 Bluefy 瀏覽器 |
| 行動電源 | 移動測試時供電，一般 5 V USB 即可 |
| （選用）3144 霍爾開關 ＋ 釹鐵硼小磁鐵 | 量自身車速，取代原本的 Radar B；三支腳的 TO-92 小晶片，不要買「49E 線性型」 |

## 2. 接線

| C4001 腳位 | 接到 | 說明 |
| --- | --- | --- |
| VIN | 擴充底板 **V** | 5 V |
| GND | 擴充底板 **G** | 一定要接 |
| TX | **GPIO16** | 雷達送資料 → ESP32 收 |
| RX | **GPIO17** | ESP32 送指令 → 雷達收 |
| OUT | 不接 | |

> ⚠️ TX、RX 是**交叉**接：雷達 TX 接 ESP32 的 RX（16），雷達 RX 接 ESP32 的 TX（17）。

### 輪速感測器（選用：自身車速）

| 3144 腳位（有字的那面朝自己，由左到右） | 接到 | 說明 |
| --- | --- | --- |
| 1 VCC | 擴充底板 **V** | 5 V（3144 需要 4.5 V 以上） |
| 2 GND | 擴充底板 **G** | |
| 3 OUT | **GPIO27** | 不用另外接電阻：ESP32 內建上拉到 3.3 V，3144 只會往下拉，不會把 5 V 送進 ESP32 |

- **安裝**：磁鐵用束帶或強力膠固定在輻條上；3144 固定在前叉或後下叉，**有字的那面朝磁鐵**，磁鐵經過時距離 5 mm 以內。
- **沒反應**：3144 只對磁鐵的一個極（S 極）有反應，把磁鐵翻面再試；也確認擴充板的 V 是 5 V。
- **測試**：轉動輪子，序列埠監看每一行最後會出現「車速 xx km/h」，騎乘頁會出現「自身車速」。
- **輪周長**：裝置頁「自身車速 → 輪周長」設成你的輪胎（預設 2105 mm＝700×25C），量法見參數旁的 ⓘ。
- 也可以用碼表常見的**磁簧開關**取代：兩條線分別接 GPIO27 和 G，不用接電源，程式相同。

**安裝方向**：雷達有元件的那面（天線面）朝後、大致水平，前面不要有金屬或厚塑膠擋住。

## 3. 燒錄韌體

### 方法 A：一鍵燒錄（推薦，不需要 Arduino IDE）

1. USB 線插在 **ESP32 板子本身**的 USB-C 孔（EN／BOOT 小按鈕旁邊）。
   > 擴充底板上的 USB 孔**只供電、不能燒錄**，插錯電腦會找不到板子。
2. 打開 `firmware` 資料夾，**雙擊 `flash.bat`**。
3. 第一次在這台電腦燒錄時：
   - 如果顯示「沒有 CH340 驅動」：輸入 `Y`，在「使用者帳戶控制」按「是」、安裝視窗按「INSTALL」，裝好後**拔插 USB 線**，再雙擊一次 `flash.bat`。
   - 如果這台電腦沒有 esptool，會自動從 Espressif 官方 GitHub 下載（需要網路）。

**成功的樣子**：

```text
[3/4] 尋找 ESP32
      ✓ 使用 USB-SERIAL CH340 (COM7)
[4/4] 燒錄中（約 20 秒，請不要拔線）
      ...
      ✓ 燒錄完成
確認 ESP32 開機訊息…
      === Radar A 後方來車偵測 v2.2.0 ===
      [Radar A] 初始化完成，開始讀取測速資料
✓ ESP32 已經在執行新韌體！
```

> 燒錄只會覆蓋程式，**ESP32 上已經調好的偵測參數會保留**。

### 方法 B：修改程式後自己編譯燒錄（開發者）

需要 Arduino IDE（內建 arduino-cli）。在 VS Code 終端機：

```powershell
cd firmware
.\arduino.ps1 setup      # 第一次：安裝 ESP32 開發板套件
.\arduino.ps1 upload     # 編譯並燒錄
.\arduino.ps1 release    # 更新 release\，讓 flash.bat 燒的是新版
```

如果出現「系統上已停用指令碼執行」，改用：`powershell -ExecutionPolicy Bypass -File .\arduino.ps1 upload`。
詳細說明見 [firmware/README.md](../firmware/README.md)。

## 4. 確認 ESP32 正常運作

看板子上的**藍色 LED**：

| LED | 意思 |
| --- | --- |
| 慢閃（0.5 秒） | 正常，等待手機連線 |
| 快閃（0.15 秒） | 手機已連線 |
| 每秒閃兩下 | 雷達離線或初始化中（剛開機約 5 秒屬正常） |
| 恆亮 | 後方來車警示中 |

開機約 5 秒後應該變成**慢閃**。如果一直「每秒閃兩下」，請檢查雷達的電源與 TX／RX 接線。

想看詳細訊息：`.\arduino.ps1 monitor`（115200 baud），可以直接輸入 `HELP`、`GET` 等指令。

## 5. 手機連線

1. ESP32 接上電（電腦 USB 或行動電源）。
2. 手機打開藍牙，用 **Chrome** 開啟 <https://bsis.mingchen.dev>。
3. 按「**連線雷達**」→ 在跳出的視窗選 **RadarA-ESP32** → 配對。
   - 如果要求「附近裝置」或位置權限，請按允許。
4. 建議在 Chrome 選單選「**加入主畫面**」，之後像 App 一樣全螢幕開啟。

**成功的樣子**：右上角顯示「● 已連線」，板子 LED 變快閃，騎乘畫面開始更新。

| 瀏覽器 | 支援 |
| --- | --- |
| Android Chrome | ✅ |
| iPhone Safari | ❌ 請改用 **Bluefy** 瀏覽器 |
| Brave | 預設關閉：網址列輸入 `brave://flags` → 搜尋「Web Bluetooth」→ Enabled → 重新啟動 |
| 電腦 Chrome／Edge | ✅（方便桌上測試） |

> ESP32 一次只能連一台裝置。電腦連著時手機會找不到，要先在電腦按「中斷連線」。

用電腦測試或展示：Windows／macOS 用 **Chrome 或 Edge** 開同一個網址（電腦要有藍牙），會自動切換成電腦版版面：左側選單、雙欄內容，騎乘頁右側多一張距離趨勢圖。

## 6. 認識畫面

| 分頁 | 用途 |
| --- | --- |
| **騎乘** | 騎車時看的畫面：警示卡（顏色 = 警示等級）、來車距離（大數字）、直立雷達條、接近速度、到達時間；下方是雷達／藍牙／ESP32 狀態，以及聲音與記錄開關 |
| **紀錄** | 60 秒距離趨勢、實車測試 CSV 記錄、來車事件列表 |
| **裝置** | 雷達原始資料、模式（室內測試／上路）、11 項參數（含輪周長）、校正步驟、指令主控台 |
| **設定** | 嗶聲、音量、提醒時機、震動、語音、危險時畫面泛紅光、保持亮屏、單位、外觀（淺色／深色）、使用說明 |

**警示顏色**

| 顏色 | 意思 | 提醒方式 |
| --- | --- | --- |
| 🟢 安全 | 後方沒有確認的來車 | — |
| 🟡 注意 | 確認有車在警示距離（預設 15 m）內接近 | 嗶兩聲、震動、「後方來車，12 公尺」，之後越近嗶越快 |
| 🔴 危險 | 到達時間 ≤ 1.5 秒或距離 ≤ 4 m | 高音快速嗶聲、每秒震動、警示卡外圈與畫面四周泛紅光 |
| 🟠 橘色 | 正在連線、等待第一筆資料 | — |
| ⚪ 灰色 | 未連線、雷達離線、資料中斷 | 長音＋「雷達離線」：**此時系統沒有在保護你** |

每個數值與設定旁邊的 ⓘ 都可以點開看完整說明。

## 7. 室內測試與校正

在「裝置」頁操作，改完的參數會存在 ESP32（換手機、斷電都不會消失）。

1. **模式選「室內測試」**：接近速度門檻暫時降到 0.1 m/s，人走路也會觸發。
2. **走近測試**：請一個人從約 6 m 外慢慢走向雷達。
   - 畫面應該出現警示；距離小於 4 m 時是「危險」。
   - 室內距離都在 4 m 內，所以通常直接顯示「危險」。想在室內看到「注意」，可以把「危險距離」暫時改成 1 m。
3. **確認方向**：裝置頁「速度核對」若顯示**正負號相反**（頁面上方也會出現提示），按提示的按鈕把「接近方向」改成另一個選項即可。設反時 ESP32 仍會用距離變化判斷、照樣警示，只是速度比較不精確。
4. **確認雷達偵測門檻是 5**（韌體 2.2 起，「裝置 → 雷達」）：人坐在雷達前 1 m 內不動時，「即時雷達資料」的目標數應該一直是 1、原始距離穩定。舊版固定用 30，人不動時幾乎偵測不到。
5. **「反射能量門檻」維持 0（不過濾）**：能量大約和距離的 5 次方成反比（實測 0.5 m 約 200 萬、1 m 約 10 萬），用近處量到的能量當門檻，遠處的車會全部被擋掉。行人改用「接近速度門檻」排除。
6. **模式切回「上路」**：接近速度門檻回到 1.5 m/s（約 5.4 km/h），走路的人就不會觸發。

> 系統只警示**正在接近**的目標：停著的車、牆壁、站著不動的人都不會警示，這是刻意的設計（市售的 Garmin Varia 自行車雷達也一樣不偵測與你同速的車）。C4001 大多不回報靜止物體，但**正對雷達的牆**會一直被回報成「偵測到目標 X m・靜止」；雷達一次只回報一個目標，牆的反射可能蓋過站在牆前的人。**室內測試時，雷達不要對著近處的牆**，請朝向至少 5 m 以上的空曠方向（走廊、大房間的對角線）或到戶外。

> 也可以點「裝置 → 工具 → 校正步驟」在手機上看這份流程。

## 8. 上路前檢查與實車測試

### 上路前檢查清單

- [ ] 「裝置」頁的模式是 **上路**（騎乘畫面沒有「室內測試模式開啟中」的黃色提示）
- [ ] 雷達朝後、略為水平，固定牢靠；線材不會被輪子或鏈條捲到
- [ ] 行動電源有電；ESP32 LED 慢閃或快閃（不是每秒閃兩下）
- [ ] 手機固定在龍頭、亮度夠、**保持網頁開著**（不要切到別的 App 或關螢幕）
- [ ] 「設定」頁：聲音開、音量足夠；按「測試警示」確認聽得到
- [ ] （建議）把韌體 `AppConfig.h` 的 `kAllowBleConfig` 改成 `false` 再燒錄：藍牙沒有加密，避免附近的人用手機改你的參數

### 實車測試

1. 在**封閉場地**（例如校內停車場）、有人看守的情況下進行。
2. 「紀錄」頁按「開始」記錄原始資料。
3. 請同學騎機車以固定速度從後方接近、超車，每種情境（汽車、機車、行人、靜止物）各做 20 次。
4. 按「停止並下載」取得 CSV；「來車事件」也可以匯出。
5. 用 Excel 計算：**偵測率** ＝ 有警示的接近次數 ÷ 總接近次數；**誤報率** ＝ 不該警示卻警示的次數 ÷ 總次數。計畫書目標：偵測成功率 90% 以上。

## 常見問題排除

| 狀況 | 可能原因 | 解決方法 |
| --- | --- | --- |
| `flash.bat` 顯示「找不到 ESP32」 | USB 插在擴充底板；或線只能充電 | 改插 ESP32 板子本身的 USB-C 孔；換一條能傳資料的線 |
| 顯示「沒有 CH340 驅動」 | 這台電腦第一次接這塊板子 | 依提示安裝官方驅動，裝完拔插 USB 再試 |
| 燒錄失敗 | COM 埠被其他程式占用；板子沒進入燒錄模式 | 關閉 Arduino IDE 的序列埠監控；按住 BOOT 鍵再燒錄，看到 `Connecting...` 後放開 |
| LED 一直每秒閃兩下 | 雷達沒接好或沒電 | 檢查 VIN／GND、TX↔16、RX↔17；ESP32 每 3 秒會自動重試 |
| 手機按「連線」沒反應 | 用 Brave（預設關閉藍牙功能） | 改用 Chrome，或在 `brave://flags` 開啟 Web Bluetooth |
| 選擇視窗找不到 RadarA-ESP32 | 已被其他裝置連線；手機藍牙沒開 | 先中斷其他裝置的連線；開啟藍牙與「附近裝置」權限 |
| 畫面顯示「資料中斷」或「雷達離線」 | 距離太遠、ESP32 沒電、雷達斷線 | 靠近一點；檢查電源與接線；網頁會自動重新連線 |
| 室內永遠是「危險」、沒有「注意」 | 室內距離都小於危險距離 4 m | 正常現象；可暫時把危險距離改成 1 m |
| 人在雷達前面，目標數卻常常是 0、數值時有時無 | 雷達偵測門檻太高（舊版韌體固定 30）；或人完全不動 | 更新到韌體 2.2，「裝置 → 雷達偵測門檻」設 5 |
| 對著牆壁時一直顯示「偵測到目標・靜止」，但沒有警示 | 正對雷達的牆反射很強，被回報成靜止目標 | 正常現象；靜止的目標不會警示。室內測試請把雷達朝向空曠的方向 |
| 人站在雷達前面，網頁卻顯示另一個距離（例如牆的距離） | 雷達一次只回報一個目標，後面的牆反射比人強 | 讓雷達朝向空曠的方向；人走動時比較容易被偵測到 |
| 室內沒人走近，卻偶爾跳出「危險」 | 室內測試模式的接近速度門檻只有 0.1 m/s，4 m 內一確認就是危險；雷達旁邊、後面的人走動也會被偵測到（波束 100° 寬） | 室內測試模式本來就很靈敏；切到「上路」模式就不會因為小動作觸發 |
| 車子明明在接近，很近才警示 | 「反射能量門檻」設太高：能量隨距離急遽變小，遠處的車過不了門檻 | 把反射能量門檻改回 0 |
| 裝置頁顯示「正負號相反」 | 雷達速度正負號與設定相反 | 按頁面上方提示的按鈕，或「接近方向」改成另一個選項 |
| 「速度核對」常常是「改用距離」 | 雷達速度與距離變化不一致（例如速度超過上限、近距離反射點跳動） | 實車時正常；若一般速度也常出現，開「記錄資料」把 CSV 給負責韌體的人看 |
| 上路後行人也會觸發 | 還在室內測試模式 | 「裝置」頁模式切成「上路」 |
| 行動電源過一下自己斷電 | 電流太小，行動電源以為充飽了 | 開啟行動電源的「小電流模式」，或換一顆 |
| 騎車時沒聲音 | 瀏覽器要先點一下畫面才能出聲；或被靜音 | 連線時有點按鈕即可；騎乘畫面確認「聲音開啟」 |

還是不行？在「裝置 → 工具 → 指令主控台」輸入 `GET`，看 ESP32 有沒有回覆 `CFG …`；或用 `.\arduino.ps1 monitor` 看序列埠訊息。
